# PARALLAX v0.3 - Generic Planner Acceptance Record

PARALLAX v0.3 removes scenario-specific answer selection from the model layer.
Both experiments use one application-manifest prompt and the same six executable
intervention capabilities. Nemotron ranks three candidates; only the top-ranked
capability is passed to Nebius Sandboxes.

## Live results

| Invariant | Nemotron selection | Control | Counterfactual | Verdict |
| --- | --- | --- | --- | --- |
| `PAY-001` | `interleave_two_actors_after_read` | 1 payment / PASS | 2 payments / FAIL | PROVEN |
| `STOCK-001` | `interleave_two_actors_after_read` | 1 sale / PASS | 2 sales / FAIL | PROVEN |

The identical capability was selected for different causal reasons and checked
against different observables. The selected capability was not hardcoded into
either prompt and was passed directly into each remote Sandbox execution.

## Model usage

- PAY-001 validated plan: 1,632 total tokens.

- The Control Deck replay makes no inference or Sandbox calls.

## Acceptance conditions

- 31 automated tests pass across Python 3.11 and 3.12 in CI.
- One generic planner prompt is used for both scenarios.
- Six capabilities are offered and executable in both fixtures.
- Nemotron must rank exactly three unique candidates in descending order.
- The selected intervention must be the top-ranked candidate.
- Unknown capabilities, malformed plans and mismatched executions fail closed.
- Only deterministic branch state can produce `PROVEN`.
- Credentials are excluded from every committed artifact.
